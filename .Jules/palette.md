## 2025-02-12 - Restoring accessibility to non-semantic UI controls
**Learning:** This application heavily relies on non-semantic HTML elements like `<div>` and `<a>` for core interactive controls (e.g., hamburger menus, carousels). While visually functional, these elements lack intrinsic keyboard support and descriptive roles. Applying `role="button"` and `tabindex="0"` isn't enough; custom elements require manually binding `keydown` event handlers for 'Enter' and ' ' (Space) to restore native button click activation patterns, ensuring full keyboard accessibility. Adding focus-visible outlines manually is also crucial.
**Action:** When working on custom interactive elements in this app's UI, I must systematically apply `role="button"`, `tabindex="0"`, descriptive `aria-label`s, AND explicitly bind a `keydown` listener for Enter and Space to manually trigger the click action. In addition, global focus styles need to be validated or added for complete keyboard accessibility.
